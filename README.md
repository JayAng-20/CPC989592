# 比較各種情況哪種方式加油比較划算-台灣中油版

這是一個可離線使用計算功能、並以已發布資料檔顯示台灣中油官方牌價的雙頁靜態網站。第一頁從 `data/cpc-prices.json` 顯示最新同步的 98、95、92 無鉛汽油零售牌價，三個油價卡片為唯讀；回饋計算仍在瀏覽器本機完成。第二頁「跳停後金額試算」沿用同一組官方油價，分別向上搜尋五項未進位金額小數部分介於 `0.300～未滿 0.400`，以及五項精確等於 `0.400` 的候選公升數，再合併排序。

GitHub Actions 會依排程從台灣中油官方 JSON 更新資料檔；網站本身不會從瀏覽器直接呼叫中油 API。若同步失敗，既有的上一筆有效資料不會被覆蓋。

首頁依序呈現「封面標題 → 台灣中油最新公告油價 → 三種油品最佳方案 → 精確有效回饋率圖表 → 98／95／92 單一油品動態排名 → 三油品綜合比較表」。完整排名使用三個按鈕切換，同一時間只顯示一張油品表格，原有欄位、手機排名卡與詳細公式均完整保留。

網站只使用 HTML、CSS 與 Vanilla JavaScript，沒有後端、資料庫、外部 API、CDN 或第三方圖表套件。所有計算都在瀏覽器本機完成。

## 跳停後金額試算

從任一頁頁首的雙頁導覽選擇「跳停後金額試算」，即可前往 `rounding.html`；按「加油回饋排名」可返回 `index.html`。第二頁會讀取目前已發布的 `data/cpc-prices.json`，並把官方最新牌價同步到既有 localStorage；不會要求使用者重新輸入油價。

操作方式：

1. 先開啟「加油回饋排名」頁面，等待官方牌價同步完成。
2. 前往「跳停後金額試算」。
3. 選擇 98、95 或 92 無鉛汽油。
4. 選擇人工加油或自助加油。
5. 輸入目前跳停公升數，最多到小數點後兩位；頁面會立即更新，也可按「開始試算」。

搜尋只會從「目前跳停公升數 + 0.01 L」開始向上增加，不會包含跳停值本身或任何更低的公升數。每個候選值使用選定模式的有效單價直接乘以候選公升數；未進位金額必須位於 `NT$20～NT$3,000`。系統會分別保留五項小數部分介於 `0.3（含）至 0.4（不含）` 的候選，以及五項小數部分精確等於 `0.4` 的候選。兩組最多各五項，不會用其中一組的額外結果補足另一組；完成後合併，依還需增加的公升數由少到多進行數值排序並重新編號，總數最多十項。

結果清單不另外顯示組別標籤。只有小數部分精確等於 `0.400` 的候選會將「未進位金額」一列顯示為高對比紅色；排名、卡片、目標公升數、增加量與四捨五入後金額都維持原有色彩。

人工與自助的單價規則為：

```text
人工未進位金額 = 人工牌價 × 候選公升數
自助有效單價 = 人工牌價 − 第一頁設定的自助每公升優惠
自助未進位金額 = 自助有效單價 × 候選公升數
```

自助模式不會先算人工總額、不會另行四捨五入折扣，也不會在整數金額上再次扣除優惠。

### 精確十進位計算

第二頁不使用 JavaScript 二進位浮點數直接判斷兩種小數條件。價格會解析成 BigInt 十進位係數 `p` 與位數 `s`，公升數則解析成百分之一公升整數 `v`：

```text
有效單價 = p ÷ 10^s 元／L
候選公升數 = v ÷ 100 L
未進位金額分子 = p × v
未進位金額分母 D = 10^(s + 2)
小數部分 F = 未進位金額分子 mod D
A 組候選 ⇔ 10 × F >= 3 × D，且 5 × F < 2 × D
B 組候選 ⇔ 5 × F = 2 × D
四捨五入後整數元 = floor((2 × 未進位金額分子 + D) ÷ (2 × D))
```

因此 `NT$320.300`、`NT$320.301` 與 `NT$320.399` 只會歸入 A 組；`NT$320.4`、`NT$320.40`、`NT$320.400` 與 `NT$320.4000` 只會歸入 B 組。`NT$320.299`、`NT$320.401`、`NT$320.410`、`NT$320.499`、`NT$320.500` 與 `NT$320.000` 不屬於任何一組。兩組分類互斥，同一候選不會重複加入。搜尋起點與 `NT$3,000` 對應的最大公升數都由整數公式推導，迴圈有明確終點。

第二頁同樣會先讀取已發布的官方資料檔；若資料檔暫時無法讀取但 localStorage 有上一筆完整資料，會保留上一筆有效牌價。若兩者都沒有，會提示回首頁確認油價同步狀態。兩頁共用原本的 localStorage key：

```text
cpc-fuel-rewards-calculator:v1
```

### 官方油價同步工作流程

`.github/workflows/update-cpc-prices.yml` 使用以下排程：

```yaml
on:
  schedule:
    - cron: "17 16 * * 0"
  workflow_dispatch:
```

GitHub Actions 的 cron 使用 UTC，`16:17 UTC` 約為台灣時間每週一 `00:17`。刻意避開整點，可以降低排程延遲集中發生的機率；也可以在 GitHub Actions 頁面按 **Run workflow** 手動同步。

工作流程只會在官方資料通過產品名稱、汽柴油零售類型、中油自營站、元／公升單位、價格、三種油品齊全、牌價生效日期及日期不倒退檢查後，才安全寫入 `data/cpc-prices.json`。資料沒有變更時不會建立空 commit；資料取得或驗證失敗時會讓工作流程失敗，但不會覆蓋上一筆有效資料。

## 共用計算定義

令：

- `A`：實際拿出的比較本金
- `r`：捷利卡儲值回饋率（例如 4% 在程式內為 `0.04`）
- `P`：汽油牌價
- `d`：自助每公升固定折扣
- `B`：捷利卡儲值後總可用餘額
- `U`：自助實際單價

共用公式：

```text
B = A × (1 + r)
捷利卡紅利金 = B − A
U = P − d

御璽卡中信紅利點數 = floor(A ÷ 30) × 3
白金卡中信紅利點數 = floor(A ÷ 30) × 2
中信紅利價值 = 中信紅利點數 × 中信紅利每點價值
```

中信紅利依「每滿 30 元」取整，不能用 `A × 0.8%` 取代。使用捷利卡加油時不會再次取得中信紅利。

## 六種方案與公式

以下所有內部運算都保留 JavaScript 浮點數完整精度，只在畫面顯示時四捨五入。

### 方法 1：星期一儲值後自助加油

```text
可加公升數 = B ÷ U
自助折讓 = 可加公升數 × d
總回饋 = 捷利卡紅利金 + 自助折讓 + 中信紅利價值
精確有效回饋率 = 總回饋 ÷ A × 100%
總等值 = A + 總回饋
有效每公升成本 = (A − 中信紅利價值) ÷ 可加公升數
廣告式回饋率 = r + 中信紅利價值 ÷ A + d ÷ P
```

交叉驗證：

```text
總回饋 = P × 可加公升數 + 中信紅利價值 − A
```

### 方法 2：星期一儲值後人工加油，VIP 購買副產品

```text
可加公升數 = B ÷ P
VIP 點數 = floor(B) × 每元 VIP 點數
VIP 價值 = VIP 點數 × VIP 購買副產品每點價值
總回饋 = 捷利卡紅利金 + 中信紅利價值 + VIP 價值
精確有效回饋率 = 總回饋 ÷ A × 100%
總等值 = A + 總回饋
有效每公升成本 = (A − 中信紅利價值 − VIP 價值) ÷ 可加公升數
廣告式回饋率 = r + 中信紅利價值 ÷ A + 每元 VIP 點數 × VIP 購買副產品每點價值
```

預設每點以 0.01 元估值，適用於複合商店、洗車或快保；這不是 2% 現金回饋，也不能直接用相同價值折抵油錢。

### 方法 3：星期一儲值後人工加油，VIP 折抵油錢

```text
可加公升數 = B ÷ P
VIP 點數 = floor(B) × 每元 VIP 點數
VIP 價值 = VIP 點數 × VIP 折油每點價值
總回饋 = 捷利卡紅利金 + 中信紅利價值 + VIP 價值
精確有效回饋率 = 總回饋 ÷ A × 100%
總等值 = A + 總回饋
有效每公升成本 = (A − 中信紅利價值 − VIP 價值) ÷ 可加公升數
廣告式回饋率 = r + 中信紅利價值 ÷ A + 每元 VIP 點數 × VIP 折油每點價值
```

預設每點以 0.005 元估值；每元 2 點時，油費價值約為 1%。

### 方法 4：中油 Pay 直接刷聯名卡自助加油

```text
可加公升數 = A ÷ U
自助折讓 = 可加公升數 × d
總回饋 = 自助折讓 + 中信紅利價值
精確有效回饋率 = 總回饋 ÷ A × 100%
總等值 = A + 總回饋
有效每公升成本 = (A − 中信紅利價值) ÷ 可加公升數
廣告式回饋率 = 中信紅利價值 ÷ A + d ÷ P
```

交叉驗證：

```text
總回饋 = P × 可加公升數 + 中信紅利價值 − A
```

### 方法 5：中油 Pay 直接刷聯名卡人工加油，VIP 購買副產品

```text
可加公升數 = A ÷ P
VIP 點數 = floor(A) × 每元 VIP 點數
VIP 價值 = VIP 點數 × VIP 購買副產品每點價值
總回饋 = 中信紅利價值 + VIP 價值
精確有效回饋率 = 總回饋 ÷ A × 100%
總等值 = A + 總回饋
有效每公升成本 = (A − 中信紅利價值 − VIP 價值) ÷ 可加公升數

```

方法 2／5 的「約 2%」與方法 3／6 的「約 1%」只描述預設的點數取得率與估值；修改進階設定後，實際比例會跟著變動。

## 廣告式回饋率與精確有效回饋率

「廣告式回饋率」把名目儲值率、中信紅利比例、自助 `d ÷ P` 或每元 VIP 點數估值直接相加。這種算法容易閱讀，但各項回饋的實際計算基準可能不同。

「精確有效回饋率」先算出實際取得的紅利金、完整公升數、固定折扣帶來的真正折讓、按 `floor` 取得的點數及其估值，再統一除以實際拿出的本金 `A`：

```text
精確有效回饋率 = 實際總回饋 ÷ A × 100%
精確與廣告式差異 = 精確有效回饋率 − 廣告式回饋率
```

差異以「個百分點」表示，可能為正、零或負；不能把它當成百分比倍數。

## 固定 0.8 元折扣為何會隨油價改變效益

```text
廣告式折扣比例 = d ÷ P × 100%
固定本金的實際額外購買力 = d ÷ (P − d) × 100% = d ÷ U × 100%
```

兩者分母不同，因此數值不相同。牌價愈低，固定 0.8 元占牌價的比例愈高；牌價愈高，自助方案的相對優勢會降低，人工加油搭配 VIP 購買副產品可能反而超越自助方案。自助折扣不是固定百分比，所以排名不能寫死。

## 損益兩平油價

比較同一付款情境下的自助折讓與人工 VIP 價值時，共同的捷利卡紅利與中信紅利會互相抵銷。令 `X` 為該情境的可用金額（儲值為 `B`、直刷為 `A`），`V` 為對應人工方案的 VIP 點數總價值：

```text
X × d ÷ (P − d) = V
P = d + X × d ÷ V
```

網站分別計算以下四組，不共用寫死的答案：

1. 儲值後自助 vs 儲值後人工 VIP 購買副產品
2. 儲值後自助 vs 儲值後人工 VIP 折油
3. 直接刷卡自助 vs 直接刷卡人工 VIP 購買副產品
4. 直接刷卡自助 vs 直接刷卡人工 VIP 折油

預設參數求得約為 `40.8／80.8／40.8／80.8` 元／公升。牌價低於交點時自助較有利；高於交點時對應的人工 VIP 方案可能較有利。若折扣或 VIP 估值為 0，網站會明示沒有有限的正牌價交點。

## 修改預設參數

一般使用者可直接在頁面「進階設定」調整，不必修改程式。

油價不再由 `calculator.js` 的預設值控制，而是由 `data/cpc-prices.json` 提供目前已發布的台灣中油官方牌價；該檔案由 `.github/workflows/update-cpc-prices.yml` 自動同步。不要在 `calculator.js`、`rounding.js` 或第二頁寫死油價。

如果要測試新的官方牌價，可在 GitHub Actions 頁面手動執行 **更新台灣中油官方油價** workflow；網站上的「更新最新牌價」按鈕只會重新讀取目前已發布的 `data/cpc-prices.json`。已經使用過網站的瀏覽器仍可能有舊版手動油價，第一次成功同步官方資料後，程式會在保留進階設定的前提下，以官方牌價覆蓋舊價格。

目前可調整的活動規則包括：

- 比較本金與星期一儲值回饋率
- 自助每公升固定折扣
- 御璽卡／白金卡的選擇（每 30 元點數規則在計算核心中定義）
- 中信紅利每點估值
- 人工加油每元 VIP 點數
- VIP 折油與購買副產品的每點估值
- 三種油價由官方同步資料檔管理，不在頁面或 localStorage 中提供手動修改
